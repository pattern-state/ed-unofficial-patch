# Full FSR 4.1.2 for Elite Dangerous: implementation plan

Agent material (AGENTS.md, Agent material): the task plan for the `fsr4-1-2` arc. Written in the `ed-fsr4` repository on 2026-11-07 and carried here as the canonical copy; the people-facing design is `docs/design-fsr4-1-2-2026-11-07.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship FSR 4.1.2 upscaling with quality modes for Elite Dangerous through ED-UP, flat and VR, Linux and Windows, and AMD frame generation on flat.

**Architecture:** ED-UP's D3D11 proxy gains the `fsr4` engine from Sean's branch, re-pinned to FidelityFX SDK 2.4, over its existing D3D11/D3D12 bridge; quality modes map to Elite's own Supersampling value; frame generation is dispatched on the bridge and presented through Elite's swapchain from ED-UP's Present hook. Our `ed-fsr4` repository is the Linux harness: isolated game copy, probe, launch receipts, automation.

**Tech Stack:** C++17 (MSVC via Wine on Linux, native MSVC in CI), Python 3 tools, FidelityFX SDK 2.4 (`amd_fidelityfx_upscaler_dx12.dll` 4.1.2.4555, `amd_fidelityfx_framegeneration_dx12.dll` 4.0.2.4555), Proton Experimental (DXVK, vkd3d-proton), ED-UP's build.bat, tools and CI workflow.

**Spec:** `docs/design-fsr4-1-2-2026-11-07.md` (decisions D1–D12, thresholds in D8). Read it first.

## Global Constraints

- Two repositories: the ED-UP fork at `~/src/ed-unofficial-patch` (branch `fsr4-1-2`, off Sean's `main` at `4aeb712e` or later) and `~/src/ed-fsr4` (harness). Paths below are relative to the repository named in the task.
- ED-UP rules apply in the fork (`AGENTS.md`): tools in `tools/` only, every tool has `--self-test`, investigation docs carry a `## Status` block, install through `tools/install_edvr.py`, logs through `tools/edvr_log.py`. Commit messages in ED-UP's style (imperative, scoped, with the flight or check run). No push to Sean's `main`; PRs only.
- SDK pins: FidelityFX SDK commit `7539ae8b6568ad29ed78a753404351daf3b5cca7` (tag v2.4.0); upscaler DLL FileVersion `4.1.2.4555`; frame generation DLL FileVersion `4.0.2.4555`. Every staged file is SHA-256 pinned.
- Provider policy (D3): `fsr4` runs on any 4.1.x provider; every label names the served version and its source; "4.1.2" appears only when 4.1.2 is served.
- Quality ratios (D4): native 1.0, quality 1.5, balanced 1.7, performance 2.0, ultra 3.0 → Supersampling 1.00, 0.67, 0.59, 0.50, 0.33.
- Thresholds (D8): image, no artefact class under `fsr4` absent under `fsr` at the same spot, frame time within 10% of `fsr`, `fsr4` price line at or below `fsr`'s on the 9070 XT; frame generation, presented ≥ 1.9× rendered over 30 s at a fixed spot, p99 presented interval within 25% of the mean, added latency ≤ 1 rendered frame, zero UI doubling, mandatory call order verified in the log. Two failures on one cause with no new hypothesis stop the track.
- Live game: only the isolated development copy on the second NVMe (`development-game.json`); never the live Steam install or prefix. Game inputs through `ed-fsr4`'s guarded helpers. Announce rendering changes before making them.
- Licence: AMD's `docs/license.md` notice ships with the DLLs; no decompilation of AMD DLLs.
- Commits: the executor asks David once, at the start, for commit authority on both repositories; without it, tasks end at "ready to commit". Commit messages are written to a file and committed with `git commit -F <file>` (Sean's rule).
- **Pushes: never by an agent.** Every push in this plan is David's, by hand, with `git push --no-verify` past the local `pre-push` hook; remotes' push URLs are disabled and the project's Claude Code permissions deny `git push`. A step that says "push" means: tell David the branch is ready and what CI should show, then wait.
- **Flown commits are never rewritten** (Sean's rule: flight logs cite the branch commit). Bring the branch up to date with `git merge upstream/main`, never rebase, never squash, never amend a commit a log names.

## Review Focus

1. A user whose Elite preset is not "Custom" (or whose `Custom.<major>.<minor>.fxcfg` is unreadable) selects a quality mode: the writer must refuse and the row must say why, never write a new file. Test in Task 3.1.
2. Proton serves 4.1.1 while the shipped DLL is 4.1.2: the label must read "fsr 4.1.1 (Proton driver provider)", never "4.1.2". Test in Task 1.2.
3. Frame generation enabled while Elite is in a map or the main menu (ED-UP's `flatRuntimeMapTemporalOff()` path, no motion vectors): FG must stand down and present single frames. Test in Task 4.3.
4. A resize or alt-tab during frame generation (`ResizeBuffers`, swapchain recreate): FG contexts and shared textures must be released before the buffers, with no present of a stale generated frame. Test in Task 4.3.
5. An uninstall or `--restore` after the Supersampling write: Elite's file must come back byte-identical from the backup. Test in Task 3.1.

**Ruling 2026-11-08 (David, option A): the FSR 4 engine flag moves to bit 9.** The merge surfaced a collision git did not report: after the branch forked, main took `edvrTemporalAa` flags bit 8 as `kTemporalFlagMapKeep` (the VR map gate), and the branch had taken the same bit, as a bare `256u`, for "the external engine is FSR 4". Left alone, the pass would pick the FSR 4 engine whenever a map was open under `fsr` or `xess`, and run the map-keep history logic on every `fsr4` frame. Options weighed: (A) FSR 4 moves to bit 9 as a named `kTemporalFlagFsr4 = 512u`; (B) the map gate moves to bit 9 and FSR 4 keeps bit 8; (D) replace the three mutually exclusive engine bits (6, 7, 9) with a two-bit engine field. A was chosen because it is one constant and six lines, all on the branch side we are already carrying: Sean's constant, his five map-gate tests and the hex his flown map-gate logs show stay exactly as they are, and nothing has to move. B rewrites his recent code inside a PR about FSR 4 for no runtime gain. D is the cleaner design but is a refactor of his ABI across every consumer and test, out of scope for a merge commit; it is noted as a possible upstream suggestion for later. The flags word is intra-DLL (setter and reader ship in one `d3d11.dll`), is never persisted and is not on the OpenXR wire, so the only visible change is the `flags=` hex in the branch's earlier flat flight logs (`102` → `202`), which no flight record cites. Cost if wrong: the constant and six lines. Extra conflicts beyond the three the plan expected (`tools/install_edvr.py`, `tools/linux_toolchain.py`, `tools/native_temporal_test/native_temporal_test.cpp`, `src/d3d11/temporal_pass.h`) were ruled mechanically and are listed in the merge commit message.
